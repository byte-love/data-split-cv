# 数据划分与交叉验证的编排实现

从桌面客户端里抽出来的「按标签分层 + 多折重复」这套评估编排。训练内核本身一行没改——内核只会做一件事：用 `training_set` 训练、用 `testing_set` 评估；四种划分方法全靠客户端编排出来。

对应源码：`src/CrossValidationUtils.cs`（核心）、`src/TempSqliteUtils.cs`（临时库连接）、`src/TrainTempModels.cs` / `src/DevTempModels.cs`（表结构 DTO）。

## 四种方法解决的是同一个问题

「只切一次数据去评估模型」这个结论不可靠。四种方法都是「把数据反复利用、多考几次再取平均」的策略——换来更可信的分数，代价是训练次数变多。

单次留出法（随机切一次 7:3）有三个毛病：

| 毛病 | 说明 |
|---|---|
| 分数靠运气 | 测试集抽到哪些样本，分数就变；换一次随机种子分数可能差很多，且看不出波动 |
| 数据浪费 | 被划走当考卷的那部分数据完全没参与训练；小数据下这是致命的（可能少 20~30% 训练量） |
| 无法回答「稳不稳」 | 「这个 0.85 可靠吗」，单次留出法答不了 |

交叉验证的思路：把数据轮流当考卷——每条数据都既被训练过、也被考过，于是能得到「平均分 ± 波动」。

## 四种方法对比

| 方法 | 核心思想 | 每条数据当几次考卷 | 训练次数 | 分数波动 | 硬性前提 |
|---|---|---|---|---|---|
| 留出法 | 随机切一次，只考一次 | 0~1 次（看运气） | 1 次 | 单次，看不出波动 | 数据要够多 |
| K 折 | 分层切 K 份，轮流拿 1 份当考卷，共 K 次取平均 | 1 次 | K 次（+1 次最终模型） | 随 K 增大变小 | 每类样本 ≥ K |
| 十折 × R 轮 | K 折取 K=10，并把整轮切分重复 R 次再平均 | R 次 | 10×R 次（+1） | 最小 | 每类样本 ≥ 10 |
| 留一 | 每次只留 1 条当考卷，其余全部训练，重复 N 次 | 1 次 | N 次（+1） | 最大（每折只有 1 条考卷，分数非 0 即 1） | 每类 ≥ 2 条，N ≤ 100 |

## 实现方式（关键：不改内核）

内核没有任何「折」的参数，所以四种方法全靠客户端编排：

1. **快照全量数据** → `cv_source`（之后每折都从它重建，保证不越跑越少）— `SnapshotSource()`
2. **按标签分层生成折映射** → `cv_fold_map`（同标签内洗牌 + 随机起始折 + 空折兜底；固定种子可复现）— `BuildFoldMap()`
3. **每折重建两张表** → `training_set` / `testing_set`（按折号从快照重建，列取两表交集）— `ApplyFold()`
4. **循环调用同一个训练程序** → 每折独立报告 + 独立模型目录（互不覆盖）
5. **读回逐折报告** → 解析 准确率 / Macro F1 / Weighted F1（+ 逐类明细）— `ParseReport()`
6. **汇总** → 平均 ± 波动；逐类指标跨折平均，support = 各折求和（= 该类总条数）— `Summarize()` / `AverageClasses()`
7. **收尾** → 用 100% 数据再训一次「最终模型」（交付给用户的模型就是这一次）— `RestoreAllToTraining()`

### 四条设计要点

- **分层**：保证每折训练集都含全部标签。内核的 `LabelEncoder` 只用训练集标签建，缺标签的那一折会被判 0 分（不是训练失败，是「没见过这个标签」）。`GetSingleSampleLabels()` 提前把这类样本找出来。
- **从快照重建，而不是「搬」**：可反复、可在中断后自愈；跑完把数据还原成「全量在训练集」。
- **逐折产物隔离**：每折报告/模型各自独立（`DeleteFoldModelDir()` / `CleanPreviousFoldArtifacts()`）。
- **固定种子**：同一份数据 + 同一个种子 ⇒ 切法完全一样，结果可复现。

### 留一的特殊处理

内核在「测试集只覆盖 1 个类别」时不生成评估报告（sklearn 的 `target_names` 限制）。所以留一改为：每折训练完再以「应用模型」模式调一次内核，取回逐条预测，由客户端自己算指标 —— `ReadDevPredictions()` / `ReadTruthLabels()` / `BuildLooFoldMetric()` / `BuildLooPooledMetric()`。

## 结果怎么读

- 顶部三个数 = 各折平均（± 波动写在日志与 `交叉验证结果.txt` 里）
- 下半部分逐类 precision / recall / f1 = 各折平均，support = 各折求和 = 该类在全部数据里的条数（所以 support 加起来等于样本总数，可自检）

## 怎么选

| 情况 | 建议 |
|---|---|
| 数据几百条以上，只想快速看效果 | 留出法 |
| 想要一个可信的分数（日常默认） | K 折 5 折 |
| 要更稳、时间也允许（定稿数字） | 十折 × 1~5 轮 |
| 数据很少（≤100 条） | 留一（或 K 折 = 最小类条数） |
| 每类样本不足 10 条 | 别用十折；K 折的折数要 ≤ 最小类条数 |
| 每类样本只有 1 条 | 四方法都会失真 —— 先补数据（内核缺标签直接 0 分） |

## 三个常见误解

- **「交叉验证的分数比留出法低/高」**：它们量的是同一件事（模型在新数据上的表现），交叉验证只是估得更稳；差异来自抽样运气和训练量。
- **「留一的波动大是不是坏了」**：不是——每折只有 1 条考卷，分数只能是 0 或 1，平均后的波动自然最大；要看整体准确率（= 对了几条 ÷ 总条数）。
- **「为什么最后还要再训一次模型」**：交叉验证的那 K 个模型只是「考试记录」，每个都少看了一部分数据；交付用的模型应当见全量数据。行业惯例：先交叉验证拿可信指标，再用全量数据训交付模型。
